# Airtable P0–P2 acceptance evidence

Date: 2026-10-10. Scope here is foundation F and Grid G1–G4. Local managed worktree; no push, deployment, release tag or published image. Other subprojects are not claimed complete.

## Foundation: implemented and isolated PostgreSQL verified

- Shared `writeCellInTransaction` preserves reference/ownership validation, record-before-cell lock order, history and overwrite hints; nullable actors propagate to expression history. `recompute:false` lets batch writes materialize once after each row.
- Protected `record.writeBatch` requires editor membership. It validates table ownership even for empty cell maps, rejects duplicate records and direct expression writes, and locks existing records and fields in stable order. Returned record IDs follow input order.
- Server budgets: 100 rows, 500 cells, 1 MiB UTF-8 serialized batch, 256 KiB serialized cell, transaction-local 30-second statement timeout. Multi-byte budget cases are exercised.
- Retry receipts share the data transaction, use `(actorKey, requestId)` and SHA256 of the body with sorted cell keys. Identical concurrent requests replay; changed bodies conflict. Actor-local cleanup uses a materialized candidate set capped at 100 expired rows and preserves seven-day live receipts. Cleanup is opportunistic, not a periodic worker.
- REST partial-success `cellErrors` implementation is unchanged; existing records-service and route regressions pass in the full suite. Client paste, public Forms, Kanban and integration enhancements remain subsequent work. The API retry documentation states that clients must reconcile instead of retrying after seven days.

## Grid G1–G4: implemented, fixture and partial browser verified; unpublished

- TSV paste uses the atomic batch writer, keeps one retry request, previews creates/updates, blocks computed fields and viewers, and waits for pagination before constructing the target records. Cross-page keyboard navigation waits for the next page; Ctrl+End stays within loaded records. Complete field reorder includes hidden fields and uses a table advisory lock.
- G4 `record.groupCounts` requires viewer membership and validates view/table ownership. A read-only repeatable-read transaction with a 30-second statement timeout applies the existing filter compiler and aggregates SQL groups. Only the first group is used; JSON values that map to the same JavaScript key merge. Empty views have no groups. Headers show full counts for loaded groups only; toolbar shows loaded/total, and query errors show `Count unavailable`.
- Flat AND filters expose existing ne/gte/lte and date equals/ne operators. Bare, nested and OR roots show a read-only explanation without rewriting the existing AST. Cell, batch, create/delete, view-option and WebSocket paths invalidate counts.
- Meaningful G4 RED: real PostgreSQL test created 202 rows and failed `No procedure found on path record,groupCounts`; four UI tests failed missing advanced-filter protection/gte. Initial GREEN: 5 tests passed. Expanded scoped GREEN: 7 files / 63 tests, including batch PG 8, counts PG 2, Grid UI 23, field-validation 18, filter UI 4, field-menu UI 2, realtime 6. Final changed UI/counts/field-order run: 3 files / 28 passed, including field-order PG 3. No PG test skipped in these opt-in invocations.
- Completion `pnpm lint` and `pnpm typecheck`: 4 packages successful. `pnpm test`: 673 passed, 32 skipped (normal opt-in PG suites), one stale G3 field-delete mock failed because delete now acquires two locks. Corrected regression explicitly verifies field-order then view-options locks and the second lock preceding view scanning; focused field-validation suite 18 passed. The normal full suite was not rerun after that test-only correction.
- Controller live browser evidence against pre-G4 dba0d6d: synthetic DOM paste completed one update and one create; complete field reorder persisted; a real API-seeded 201-row table showed 200/201, Ctrl+End selected row 200, ArrowDown loaded and selected row 201. A 390px viewport was usable after closing history. These observations do not establish native clipboard or G4 full-count live acceptance. Native OS clipboard automation was permission blocked; live group-count error/filter/viewer browser cases remain pending controller verification. No push, deployment or release occurred.
