## Foundation: implemented and isolated PostgreSQL verified

- Shared `writeCellInTransaction` preserves reference/ownership validation, record-before-cell lock order, history and overwrite hints; nullable actors propagate to expression history. `recompute:false` lets batch writes materialize once after each row.
- Protected `record.writeBatch` requires editor membership. It validates table ownership even for empty cell maps, rejects duplicate records and direct expression writes, and locks existing records and fields in stable order. Returned record IDs follow input order.
- Server budgets: 100 rows, 500 cells, 1 MiB UTF-8 serialized batch, 256 KiB serialized cell, transaction-local 30-second statement timeout. Multi-byte budget cases are exercised.
- Retry receipts share the data transaction, use `(actorKey, requestId)` and SHA256 of the body with sorted cell keys. Identical concurrent requests replay; changed bodies conflict. Actor-local cleanup uses a materialized candidate set capped at 100 expired rows and preserves seven-day live receipts. Cleanup is opportunistic, not a periodic worker.
- REST partial-success `cellErrors` implementation is unchanged; existing records-service and route regressions pass in the full suite. Client paste, public Forms, Kanban and integration enhancements remain subsequent work. The API retry documentation states that clients must reconcile instead of retrying after seven days.
