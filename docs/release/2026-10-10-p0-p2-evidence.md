## Foundation: implemented and isolated PostgreSQL verified

- Shared `writeCellInTransaction` preserves reference/ownership validation, record-before-cell lock order, history and overwrite hints; nullable actors propagate to expression history. `recompute:false` lets batch writes materialize once after each row.
- Protected `record.writeBatch` requires editor membership. It validates table ownership even for empty cell maps, rejects duplicate records and direct expression writes, and locks existing records and fields in stable order. Returned record IDs follow input order.
- Server budgets: 100 rows, 500 cells, 1 MiB UTF-8 serialized batch, 256 KiB serialized cell, transaction-local 30-second statement timeout. Multi-byte budget cases are exercised.
- Retry receipts share the data transaction, use `(actorKey, requestId)` and SHA256 of the body with sorted cell keys. Identical concurrent requests replay; changed bodies conflict. Actor-local cleanup uses a materialized candidate set capped at 100 expired rows and preserves seven-day live receipts. Cleanup is opportunistic, not a periodic worker.
- REST partial-success `cellErrors` implementation is unchanged; existing records-service and route regressions pass in the full suite. Client paste, public Forms, Kanban and integration enhancements remain subsequent work. The API retry documentation states that clients must reconcile instead of retrying after seven days.

## P4: Form builder, anonymous page, and share/RSS gates

Implemented locally on 2026-10-10, unpublished. P4 adds the Form renderer and
creation control after P1–P3 configuration/publication/submission services. It does
not add a migration. Existing ADR-0012 covers the subsystem. No push, deploy,
release tag, or image publication occurred.

- V1: TableView mounts FormBuilder for Form and GridEditor only for Grid; the
  container regression confirms Form never mounts Grid. Form creation is enabled;
  Kanban creation remains unavailable.
- P1: Builder offers only the six supported public types; title/description/success
  limits, 1–50 selected fields, order, and required settings use the shared schema.
  Required booleans have an explicit must-be-checked label; zero survives number
  normalization. Native labeled controls and narrow-layout classes are implemented.
- P2: Viewer has a disabled preview, editor can save configuration, owner alone has
  publication controls. Default 30-day expiry and 1–365-day input bounds, one-time
  in-memory URL/copy, rotation confirmation, revocation confirmation, publication
  expiry/status, and configuration-invalidation guidance are implemented.
- P3/P4: Public page uses safe getPublicForm projection via a type-only client
  contract, force-dynamic rendering, noindex/nofollow/no-referrer metadata, plain
  text, and native controls. It does not display record IDs. Pending attempts are
  blocked; uncertain retries keep the exact body and UUID. Edits or 409 receipt
  conflicts require explicit confirmation and a new UUID, with duplicate warning.
- Share create rejects Form before minting a token. Shared-view resolution rejects
  legacy Form shares for metadata/records and its RSS/attachment consumers. An RSS
  route regression uses the real shared-view resolver and verifies 404 before any
  records query. `agent-access/rss.ts` is a pure XML formatter; the type gate belongs
