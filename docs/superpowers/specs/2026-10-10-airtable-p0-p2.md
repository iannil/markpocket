# Airtable P0–P2：范围与接口设计

日期：2026-10-10。用户授权：P0–P2 全部纳入实施计划。本轮交付设计与计划，不代表已经实施或发布。各子项目可独立验收。Lookup/Rollup 是前次建议的单独架构决策项，不属于 P0–P2；本轮不加入。

## 全局约束

- Node >=22；pnpm 10.32.1；PostgreSQL 16；沿用 Next.js 16、React 19、tRPC 11、Drizzle、Vitest 3。
- 单租户自托管；一个应用进程加 PostgreSQL；不引入 Redis、外部队列、额外常驻服务或新的运行时依赖。
- 保持 ADR-0001/0003/0004：表设计小于 100,000 行；Expression Field 单记录作用域；不增加 Lookup/Rollup、公式依赖图或多租户。
- 写操作沿用 ADR-0005：empty 删除 cell、非法值拒绝、每次实际改值记录历史、Expression 在同事务物化；实时通知在提交后发送。
- 基于现行 Paper & Ink 设计；界面文案使用英文；不显示未交付的视图类型；支持键盘与窄屏。
- API 与 UI 均执行成员权限；公开表单仅授予提交能力，不授予读取记录、附件或成员的能力。
- 不保存 Airtable PAT；不输出凭据、完整 Webhook URL 查询参数或签名密钥到日志与报告。
- 保留用户现有 .gitignore、CLAUDE.md 删除和 apps/web/next-env.d.ts 修改；不得使用 git add . 或恢复这些改动。
- 新子系统必须随实现提交 ADR；数据库迁移使用 pnpm db:generate，不手改已应用迁移或猜测迁移编号。
- 每个子项目独立提交；不推送分支、创建发布 tag、发布镜像或部署外部服务。

## F：原子写入公共能力

F1：抽出 cell.upsert 已有事务内实现为 writeCellInTransaction，调用者明确传事务、actorId、recordId、fieldId、value。保留其归属、锁、历史、引用检查与覆盖提示。Expression 写入 actorId 支持 null；公共表单使用 null，不伪装成表单所有者。

F2：新增 record.writeBatch({tableId, requestId, rows})，rows 为 {recordId?:string,cells:Record<string,unknown>}[]；无 recordId 新建。最多 100 行、500 个 cell、1 MiB 序列化输入、每 cell 256 KiB，单事务、30 秒 statement_timeout。任何一个非法值整批回滚。成员 editor 以上；所有 ID 同表；不允许手写 expression。按 recordId/fieldId 稳定加锁，写完一行只重算一次表达式。保留旧 REST 部分成功协议，不悄悄改成原子行为。

F3：持久 write_receipt，唯一 (actorKey,requestId)，保存 bodyHash 和结果；相同 key 同请求重放结果，不同 body 409；事务内 receipt 与数据同提交，成功但响应丢失可安全重试。actorKey 为 user:<id> 或 form:<publicationId>，由服务端生成；收据保留 7 天，超过保留时间 UI 明确不能继续重放。

## G：Grid

G1：通过原生 paste 事件读取 text/plain，支持 TSV 双引号、转义引号、引号内换行、CRLF、尾部单行结束符。编辑输入框内粘贴保留文本行为。矩形区域最多 100×实际字段数且总 500 cell；超过字段宽度、空选区、不可写字段、非法值均在提交前拒绝。使用现有 parseClipboardValue 逐类型转换，服务端再次验证。

G2：从选中格起覆盖已加载行；需要更多现有行时先加载，不得把尚未加载的记录当新行。只有无 filter/sort/group 的默认顺序且到达实际末尾时允许追加新行；否则越界拒绝并提示。先显示覆盖/新增数，用户确认具体写入；pending 期间冻结本次 ID 矩形。超时重试复用 requestId；不自动重放写入。编辑状态/视图切换取消准备阶段。

G3：field.reorder({tableId,fieldIds}) 提交完整去重字段集合；与 create/delete 使用相同 field-order:<tableId> advisory lock，事务更新 orderIndex；列表 orderIndex,createdAt,id。上移/下移按钮和快捷可访问菜单即可，不增加拖拽库。

G4：record.groupCounts({tableId,viewId}) 使用 SQL 全量过滤后聚合，不受加载页影响；返回 {total,groups:[{key:string|null,count:number}]}。group key 与 applyGroup 一致；最多首个 group 生效并在 UI 显示。Grid 标题显示 loaded/total；只返回计数不全量拉取数据。

G5：ArrowDown/Tab/PageDown 到已加载末端请求下一页，防重复、等待成功后移动到目标格；失败可重试、换视图清除待选中目标。Ctrl+End 仅最后已加载行，不自动拉全表。补齐已有 ne/gte/lte 操作符；不得摊平或覆盖服务端已有嵌套过滤器，嵌套配置显示只读说明。

## M：迁移可信度

M1：在现有导入报告基础上增加人可读摘要和表级结果、snapshot/skip 分类，不重新写导入器。保留 JSON 下载与 requestId 恢复。不得展示 PAT 或附件原始 URL。

M2：预览显示所有当前预算：20 表、每表 100 源字段、总 10,000 records、100,000 非空 cell、16 MiB records JSON、200 唯一附件、单附件 10 MiB、总附件 64 MiB、120 秒。schema 预览无法知道记录/附件实际数时明确“Checked during import”，不得冒充预检已通过。保留超限回滚。

M3：新增 opt-in live test，使用用户提供的只读 PAT 和专门测试 Base，以及独立 PG/上传目录；源只读，不改 Airtable。核对完整来源记录集合、跨表链接、select、checkbox、附件字节哈希、snapshot、重复 requestId。测试 Base 准备契约写入文档。没有 PAT 时记录 blocked，不用 fixture 替代。凭据只走环境/受保护本地配置，不进命令行值或日志。

M4：复用 scripts/backup-instance.sh 与恢复指南，构建候选本地镜像，空实例安装→备份→带新迁移升级→隔离恢复旧镜像加旧快照。不可用旧程序直接连接已升级 schema 当回退。输出候选 commit、镜像 ID、命令退出码、恢复校验；不发布镜像/tag。

## V：视图容器

V1：TableView 负责 field/view/member 加载、activeViewId 与 ViewTabs；GridEditor 保留 Grid 交互，传入受控 viewId，不为 Form/Kanban 运行 Grid 数据 hooks。Form 交付时才启用 form，Kanban 交付时才启用 kanban；公开只读分享维持 Grid 渲染并使用相同投影，form 不可作为只读 share。

## P：Form

P1：ViewOptions.form={title,description,fields:[{fieldId,required}],successMessage}；最多 50 字段，title≤120、description≤2000、successMessage≤500。只支持 text/number/boolean/date/single-select/multi-select；不做公共附件上传、user/link/expression、条件逻辑。布尔必填为必须勾选（明确标签），数字 0 合法。

P2：owner 可发布/轮换/关闭表单，editor 可编辑配置；发布表保存 hashed 随机 token、prefix、viewId FK cascade、createdBy、revokedAt、expiresAt。只显示 token 一次，刷新后可轮换，撤销旧链接。发布者失去 owner 身份即不可提交。新增字段不自动暴露；字段删除/类型变化使受影响发布失效，禁止悄悄放宽配置。

P3：公开 GET 仅返回明确选择的可写字段及安全 options；POST 接受 {requestId,cells}，缺少必填/额外字段/非白名单类型/失效配置均拒绝；提交复用 F 原子写，响应 {ok:true}，不返回 recordId。GET/POST 都 no-store/no-referrer；POST 同源检查，body 64 KiB，包括 chunked，默认每发布 30 提交/分钟、单进程总 120/分钟。限流是滥用门槛，非垃圾内容防护承诺。不信任任意 X-Forwarded-For。

P4：匿名记录 createdBy/changedBy=null，增加 form_submission(publicationId,requestId,recordId,createdAt) 内部审计，无个人身份伪造。receipt 主键作用域为 publication，轮换产生新 publication。10 分钟过期不是默认：默认链接 30 天，owner 可设 1–365 天。

## K：Kanban

K1：ViewOptions.kanban={groupFieldId,titleFieldId?}；group 必须同表 single-select，title 为 text/number/date/single-select，最多 100 个选项。空状态独立列，未知旧 choice 值进入 Unavailable 列且不能拖入。

K2：每列 50 张独立分页，使用 server record.kanbanPage({tableId,viewId,choiceId:string|null,offset,limit})，复用 filter/sort 和确定性 id 排序；列计数来自 SQL，不以加载卡片数充当总量。不要加载全表再前端分列。

K3：拖动通过 cell.upsert 写 group 字段，只修改状态、不改变卡片自定义排序。提供 Move to 菜单覆盖键盘/触屏；viewer 不能拖动或写入。失败恢复旧状态，成功 invalidate 卡片、计数、Grid；LWW 提示继续展示。按 filter 移出视图的卡片正常消失。

K4：详情抽屉用现有字段显示/编辑能力；通过新增 record.get 受保护读取单条记录，viewer 只读。不暴露 Form 管理能力。字段删除或 group 类型变化后显示配置修复界面，不退化为全表无过滤视图。

## I：Token 与自动化

I1：api_token 增加 access='read'|'write'、baseId nullable FK ON DELETE CASCADE；老 token 保留 write/all，新的 UI 默认当前 Base/read/30 天；允许 1–365 天或明确选永不过期。到期边界 expiresAt <= now 即拒绝。

I2：Token 能力是创建者当前成员权限的交集。REST 与 MCP 共用 AsyncLocalStorage 请求作用域，并在 assertRole 拒绝越 Base/只读写入；base.list 必须过滤，base.create 在 bound token 下拒绝。受限请求 protectedProcedure 明确 allowlist，未知路径默认拒绝；不能通过 token.create、share.create 等转出更宽凭据。保留现有全权限 token 的已公开 CRUD 行为，浏览器 session 无限制变化。直接 getRecord 路径同样通过 assertTableRole 覆盖。

I3：Webhook 本轮纳入完整有限范围：owner 为每表配置最多 5 个 HTTPS endpoint，订阅 record.changed/record.deleted；payload 仅 eventId、type、baseId、tableId、recordId、occurredAt，无 cell 值。消费者需单独受限 Token 拉取数据；删除只凭 ID 处理。导入与 CSV 也产生事件，文档明确初次导入可能形成大量通知。

I4：PostgreSQL trigger/outbox 保证所有 record/cell 写路径，包括插件和导入，提交才可见、回滚无事件。按 (subscriptionId,txid,recordId) 去重，事务内多 cell 修改合并；删除优先。数据库存储交付状态，应用内单 worker 每秒拉最多 20 个、并发 2、租约 30 秒，用 SKIP LOCKED。最多 5 次自动尝试，间隔 1s/10s/60s/300s；2xx 成功，408/429/5xx/网络失败重试，其他 4xx/3xx 终止。请求超时 5 秒、响应读取至多 64 KiB，禁跟随重定向；至少一次交付，接收方按 eventId 去重。

I5：每次发送重新解析 DNS、拒绝任何非公网 IP、固定已验证地址且保持 TLS hostname。仅 HTTPS/443、无 URL userinfo/hash，URL≤2048 字符。查询参数可用但不得日志输出。防 SSRF 不能复用仅允许 airtableusercontent.com 的域名规则；复用/提取公网地址判断与受控 transport，不放宽 Airtable 现有规则。

I6：每 endpoint 随机 32 字节签名密钥，使用独立 WEBHOOK_ENCRYPTION_KEY（32-byte base64）AES-256-GCM 存储，不派生自会话 secret。签名 HMAC-SHA256(timestamp+'.'+rawBody)，头 X-MarkPocket-Event/ Timestamp/Signature。密钥仅创建/轮换时返回；轮换清除在途 lease，待发送任务使用新密钥，已发请求可能旧密钥完成须文档说明。

I7：pending/leased 共计每 endpoint 最多 10,000；溢出时暂停 endpoint、写可见 overflow 状态并停止收集新事件，不让业务写入失败。明确缺口时间且不可声称无损；恢复需 owner 确认并自行全量对账。保留终态日志 7 天并定期批删；owner 可看失败状态、暂停/恢复和对单条 dead 手动重试；URL 修改创建新订阅而非改变旧任务目标。成员 owner 权限失效暂停发送；Base/Table 删除 cascade 丢弃对应待发任务。

I8：生产 worker 与 server.ts 生命周期一致，SIGTERM 停止 claim、等待或中断在途请求后关 PG。dev 通过手动一次性 worker 命令验收，不再加常驻服务。缺 key 不启动发送并显式显示 disabled，不丢 pending。

## 验收与计划映射

F→foundation；G→grid；M→migration-readiness；V/P→forms；K→kanban；I→integrations。执行顺序 F→G→M→P→K→I→整体验收。F 完成后 M 可独立推进；本轮不要求并行 agent。各子计划包含实际代码片段、测试与提交路径，总计划定义统一门槛。真实凭据缺失只阻塞 M3 和取消 preview 声明，不阻塞其他授权工作。
