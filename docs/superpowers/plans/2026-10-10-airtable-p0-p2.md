# Airtable P0–P2 Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成用户授权的 P0–P2：Grid、迁移验收、Form、Kanban、Token 限权与可靠 Webhook。

**Architecture:** 六个可独立验收子项目串行衔接，公共写入先行。保留单租户与现有部署形态，公开 Form 使用独立提交能力，Webhook 使用 PostgreSQL outbox 和同进程 worker。

**Tech Stack:** Node >=22, pnpm 10.32.1, PostgreSQL 16, Next.js 16, React 19, tRPC 11, Drizzle, Vitest 3.

**Spec:** `docs/superpowers/specs/2026-10-10-airtable-p0-p2.md`。

## Global Constraints

- Node >=22；pnpm 10.32.1；PostgreSQL 16；沿用 Next.js 16、React 19、tRPC 11、Drizzle、Vitest 3。
- 单租户自托管；一个应用进程加 PostgreSQL；不引入 Redis、外部队列、额外常驻服务或新的运行时依赖。
- 保持 ADR-0001/0003/0004：表设计小于 100,000 行；Expression Field 单记录作用域；不增加 Lookup/Rollup、公式依赖图或多租户。
- 写操作沿用 ADR-0005：empty 删除 cell、非法值拒绝、每次实际改值记录历史、Expression 在同事务物化；实时通知在提交后发送。
- 基于现行 Paper & Ink 设计；界面文案使用英文；不显示未交付的视图类型；支持键盘与窄屏。
- API 与 UI 均执行成员权限；公开表单仅授予提交能力，不授予读取记录、附件或成员的能力。
- 不保存 Airtable PAT；不输出凭据、完整 Webhook URL 查询参数或签名密钥到日志与报告。
- 保留用户现有 .gitignore、CLAUDE.md 删除和 apps/web/next-env.d.ts 修改；不得使用 git add . 或恢复这些改动。
- 新子系统必须随实现提交 ADR；数据库迁移使用 pnpm db:generate，不手改已应用迁移或猜测迁移编号。
- 每个子项目独立提交；不推送分支、创建发布 tag、发布镜像或部署外部服务。

## Scope Decisions

- 用户“P0–P2 全做”包含 P2 的 Token 与 Webhook，Webhook 是完整有界交付，不是仅一段调用示例。
- Lookup/Rollup、完整公式迁移、自动化画布、Interface Builder、插件商店与多租户不在本轮。
- Form 首版为标量与选择字段，公开附件/关系选择不暴露内部数据；Kanban 用 single-select，不做卡片手动排序。
- 原 REST 写入的 cellErrors 部分成功协议保持；新粘贴与 Form 用明确原子接口。
- 文档引用的历史测试通过不等于当前分支验证。M3 无凭据时只标该任务 blocked，其余继续；取消 import preview 的声明必须等真实验收与发布门槛。

列序与 view-options 锁：需要两者时始终 field-order → view-options。公共写入先 receipt advisory，再现有 record IDs 排序取行锁，再 cell advisory；单格 writer 也须 record-before-cell。Form 外层先 view-options/发布与成员共享锁，再 receipt/record；不得反向调用发布管理。Worker 不持 DB 事务跨网络请求。
