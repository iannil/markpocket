## 二、设计系统与视觉语言

**做得好**：
- **Token 体系完整**：radius 从 0.375rem 派生出 sm→4xl 全尺度（`globals.css:50-89`），色彩/边框/状态色全部语义 token 化，未发现裸色值泛滥。
- **字体策略正确**：Inter + JetBrains Mono 全部 @fontsource 自托管（性能 + 隐私 + 离线），数字列 `tabular-nums` + mono 的组合是数据工具的正确选择。
- **密度语言统一**：行高 32px / 表头 36px（Paper & Ink spec §4.3）在网格、历史表、设置列表中保持一致；"hairline 分隔优先于卡片容器"的取向符合高密度工具最佳实践。
- **动效克制且有据**：加载条（spec §7.4）、骨架屏、`animate-pulse` 仅用于状态指示，无装饰性动效——对工具产品是正确取舍。

**发现**：
- **[UX-P2] 暗色模式是"半成品态"**：`globals.css:101` 定义了完整 `.dark` token 组，但全产品无切换入口、组件无 `dark:` 用法。要么补齐（roadmap），要么明确文档化"仅浅色"以管理预期。自托管运维工具用户深夜使用场景真实，建议列入 roadmap 而非删除。
- **[UX-P3] 品牌存在感弱**：登录页纯文字 wordmark，无 logo mark、无产品截图/插画。自托管产品的 trust 建立也可借助视觉（Open Project / NocoDB 均有），属可选增强。

## 三、信息架构与导航

**结构**：`/bases`（工作区）→ `/bases/[id]/tables/[tid]`（网格）+ `/settings/*`（六标签）+ `/history`。三层深度合理，侧栏二级展开当前 base 的表，面包屑双槽（Workspace ▸ Base ▸ 叶子）稳定。

**发现**：
- **[UX-P1] 设置区六标签的命名层级略平**：Tables / Members / Agents / General / History / Export 并列，但用户心智中 General（base 名称、危险区）应是第一标签。实测"改个名字"需要点进第 4 个标签。建议：General 提到首位，或把 Base name 提升为设置首页内容。
- **[UX-P2] 侧栏无当前表高亮以外的上下文**：多 base 多表后，侧栏是唯一全局导航，但无 base 图标（icon 字段存在于数据模型且公开页在用）、无表数量徽标、无搜索/过滤。50+ base 用户将依赖 ⌘K。
- **[UX-P2] 命令面板无最近访问/频率排序**：cmdk 支持自然排序，但无 recency 加权；高频表的跳转成本恒定。

## 四、生产力主路径（网格编辑器）—— 本次审计重心

### 4.1 🔴 UX-P0：表达式字段的创作与可读性

截图证据（13-field-edit-dialog）：编辑 "Double" 表达式字段时，输入框内容为 `{5cd718dd-2407-4182-a233-a1e811de1348} * 2`，提示文案 "Use {fieldId} tokens. Arithmetic on number fields only."。

- **创作不可能**：用户必须知道并手打/粘贴 36 字符 UUID。无字段选择器、无 token 插入、无自动补全。除开发者外无人能完成此操作。
- **可读性为零**：列头同样显示原始表达式（UUID 形态），他人打开表格完全无法理解该列依赖什么。
- **对比**：Airtable 公式编辑器提供字段自动补全 + 语法高亮；Notion 公式 2.0 是可视化构建器。本项目 ADR-0003 明确选择了"表达式而非 Formula DSL"的架构取舍，但**展示层不应把内部标识符暴露给用户**。

**建议**（按投入递增）：① 列头/对话框显示 `字段名` 替代 UUID（`{Age} * 2`），编辑时双向转换；② 输入 `{` 弹出字段名补全菜单；③ 对话框内嵌可用字段列表（点击插入）。

### 4.2 🔴 UX-P0：筛选空结果与真空表不可区分

截图证据（17-grid-filtered-empty）：带一个空值条件筛选后网格中央显示 "No records."——与真空表（24-grid-empty-state）完全同文案。视觉模型评分 4/10。

- 唯一线索是工具栏 `Filter (1)` 计数徽标，位于视线焦点（网格中央）之外，**注意力断链**。
- 实测还发现：**空操作数条件会静默过滤全部记录**（equals + 空串无值校验），用户极易在不知情时触发。
- 无快速"清除筛选"入口；需重开面板逐条删条件（实测一次删除点击还因面板重渲染失效需重试）。

**建议**：① 空结果时差异化文案 "No records match your filters" + 行内 "Clear filters" 按钮；② 条件行操作数为空时给黄色警示或禁止应用；③ Filter 按钮在生效时除计数外加背景强调色。

### 4.3 🔴 UX-P0：新表零引导

截图证据（24）：新表打开后：无字段列、中央 "No records."、底部 "+ new record"。评分 5/10。

- 用户面对先有鸡还是先有蛋的困境：建记录需要字段，建字段入口是右上 "+ field"。
- **Airtable 惯例**：新表默认自带 Name 列，用户即刻可输入。本项目 record.create 甚至允许无字段建记录（产生空行）。

**建议**：新表默认创建 "Name" 文本字段（服务端 table.create 同事务建列，与默认 Grid 视图同模式）；或空表状态给出分步引导（1. 建字段 → 2. 加记录）。

### 4.4 🟡 UX-P1：单元格历史侧栏常驻挤压网格

截图证据（05）：dock 打开后网格 952→712px（-25%）。列少时可用，6 列以上必触发横向滚动且破坏正在进行的视觉扫描。评分 7/10。

**建议**：dock 可折叠为窄条（图标态）；或改为浮层（底部 sheet）；至少记住用户折叠偏好。

### 4.5 🟡 UX-P1：表头交互语义

单击列头 = 切换排序，双击 = 编辑字段（tooltip 有说明）。来自 Airtable 的用户预期单击打开下拉菜单（排序/编辑/重命名/插入列均在菜单）。当前双击编辑的发现性依赖 tooltip。**建议**：列头右侧加 ⌄ 菜单触发器（含 Sort asc/desc、Edit field、Insert left/right），保留单击排序快捷。

### 4.6 ✅ 键盘交互是全产品最强项

实测验证：方向键/Home/End/PageUp/PageDown/Ctrl+方向、Tab 跨行换行、Enter/Space 布尔切换、type-to-edit、Delete/Backspace 清空、⌘C/⌘V 带类型解析的复制粘贴、Escape 清除选择、IME 组合态守卫、行选择 shift/⌘ 多选。**达到 Airtable 级**，超过 Notion 表格。这是应当对外宣传的产品能力。

### 4.7 其他网格发现

- **[UX-P1] 无撤销体系**：删除记录是 toast 通知 + 无 undo。Airtable 的 trash/undo 是数据工具的安全网。至少对 delete record/clear cell 提供 5 秒 toast undo（数据软删除已有历史行，技术上可行）。
- **[UX-P2] 行悬停删除按钮发现性**：× 仅 hover 出现（选中行也出现——前轮修复），但无文字标签，鼠标用户首次难以发现。建议 hover 时显示 "Delete" 文字或垃圾桶图标。
- **[UX-P2] 分组选择器是下拉**：Airtable 的分组是菜单+多级，此处单选下拉可用但仅支持单字段分组（数据模型如此），UI 未说明该限制。
- **[UX-P2] 列宽调整无自适应列宽入口**（双击分隔符 auto-fit 是行业惯例）。

## 五、表单与错误反馈

- **[UX-P1] 注册/登录错误无字段级视觉标注**（03-register-mismatch，6.5/10）：`aria-invalid` 已设置（读屏可感知）但输入框无红描边、无图标，错误消息在按钮上方而非出错字段下方。HTML5 原生校验气泡（minLength）与自定义错误样式并存，视觉语言割裂。
- **[UX-P2] 密码强度无反馈**：仅 "at least 8 characters" 静态提示，无强度指示。
- **[UX-P2] 邀请表单提交无 email 存在性预检**：输入已邀请邮箱会作废旧邀请静默重发（服务端设计正确），但 UI 可提示"将替换现有邀请"。
- **✅ 好实践**：错误文案具体（"Invalid email or password" 而非 "Error"）、服务端权威校验、错误不泄漏内部信息。

## 六、设置区与危险操作

- **✅ 确认体系整体专业**（前轮修复后）：删除 base/字段/视图/分享链接/邀请、移除成员、撤销 token、恢复历史、自降级共 9 处确认全部 Dialog + destructive 样式 + 后果文案（"permanently deletes every table, field, and record"）。20-delete-base-confirm / 23-revoke-token-confirm 评分均 8+/10。
- **[UX-P2] 一次性机密两种展示模式并存**：邀请链接用内嵌面板（21，评分 8/10——上下文连贯性更好），API token 用模态框（22）。建议统一为面板模式（打断更少）。
- **[UX-P2] token 列表无最后使用高亮**："never used" 的 token 长期闲置无任何视觉提醒，建议超 90 天未用的 token 标灰提示轮换。

## 七、公开页与邀请流

- **✅ 公开分享页（15）完成度高**：表格语义、表切换 tablist、骨架屏、Show more 计数、无结果/过期链接差异化文案（18）。作为匿名访客的首次接触面，干净专业。
- **[UX-P2] 分享页无 base 图标/favicon 差异**：`getBase` 已返回 icon 字段但 header 仅小尺寸显示；社交分享无 OG 卡片（`openGraph` 已设 title，无描述/图）。
- **[UX-P2] 邀请页（16）Accept 后无成员视角预告**：接受前看不到表结构预览（安全合理），但可在卡片中展示 "3 tables · 4 fields" 级别的规模信息降低接受决策成本。

## 九、可访问性 UX

- **[UX-P1] 焦点可见性**：网格/命令面板键盘焦点依赖 ring，但部分 hover-only 控件（侧栏设置图标已修 focus-visible）模式仍散布；表单错误无视觉标注（五）。
- **[UX-P2] 对比度抽查**：muted-foreground 辅助文字（[10px] 级别的类型标签、时间戳）在浅背景上接近 4.5:1 边界，建议跑全站对比度审计（axe）。
- **✅ 已具备**：全网格 aria 矩阵（role/rowcount/colcount/activedescendant/aria-sort）、toaster role=status、对话框语义、`aria-invalid`。

## 十、移动端

横向滚动可用、无破版（19/20 截图 PASS），但工具类产品的移动体验止步于"查看+轻编辑"：网格工具栏在 390px 换行两行、字段对话框无移动适配、侧栏无抽屉模式。**定位判断**：自托管数据工具，移动非核心场景，维持现状合理；建议仅保证只读浏览（分享页已达标）与成员管理两个高频移动任务的可用性。

## 十一、修复路线图（按 UX ROI 排序）

1. **表达式可读化**（4.1）：UUID→字段名双向显示 + `{` 补全 —— 解锁核心功能可用性
2. **筛选空结果差异化 + 空值防护 + 行内清除**（4.2）—— 一小时的改动消除最大困惑源
3. **新表默认 Name 列**（4.3）—— 服务端一行改动 + 空态分步引导
4. **表单字段级错误标注**（五）—— 输入框红描边 + 错误消息移至字段下
5. **删除记录 toast undo**（4.7）
6. **历史 dock 可折叠**（4.4）+ **列头菜单**（4.5）
7. **设置标签重排（General 首位）**（三）+ **一次性机密统一面板模式**（六）
8. **暗色模式补齐或文档化**、**快捷键 ? 速查面板**、**对比度全站审计**（九）
